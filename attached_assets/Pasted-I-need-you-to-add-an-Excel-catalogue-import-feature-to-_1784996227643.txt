I need you to add an Excel catalogue import feature to the PinHunt UK app and import the attached workbook into the existing Supabase database.

The workbook is:

PinHunt_UK_Master_Seed_13000_Pins.xlsx

It contains approximately 13,000 catalogue records. Some records are source-verified, while many are speculative seed records intended to be corrected and improved by users over time.

Objective

Build a safe, repeatable Excel import process that:

1. Reads the Master Catalogue worksheet.
2. Maps each spreadsheet row into the existing pin catalogue database.
3. Preserves the distinction between verified and speculative records.
4. Prevents duplicate imports.
5. Produces a clear import report.
6. Supports future re-imports and updated versions of the workbook.

Do not replace or damage existing production data.

First inspect the existing app

Before changing anything:

* Inspect the current Supabase schema.
* Identify the existing pin catalogue table and related tables.
* Reuse the current schema where practical.
* Check whether there are already fields for manufacturer, character, collection, year, edition size, images, confidence, verification or source.
* Create a migration only where required.
* Do not create a completely separate catalogue system unless the current schema genuinely cannot support the import.

Verification and seed logic

Use the workbook’s verification status to classify each record.

Suggested mapping:

Verified records

Statuses containing terms such as:

* Source verified
* Official
* Verified
* High

Set:

is_seed_record = false
needs_review = false

Speculative records

Statuses containing terms such as:

* AI expanded
* speculative
* Medium
* Low
* Seed

Set:

is_seed_record = true
needs_review = true
confidence_level = medium or low

Do not present speculative records in the UI as confirmed facts.

In the pin detail page, speculative records should display a small label such as:

Community verification needed

Do not use alarming wording such as “fake” or “invalid”.

Duplicate protection

Use pinhunt_id as the primary import key where available.

The import must be idempotent.

Re-importing the same workbook must not create another 13,000 rows.

Use an upsert strategy:

* If pinhunt_id exists, update the existing catalogue record.
* If it does not exist, insert it.
* Never overwrite user-contributed images or corrections with blank spreadsheet values.
* Never downgrade a community-verified or admin-verified record back to speculative.
* Do not overwrite newer manual edits unless the importer is explicitly told to do so.

Create a normalised fallback duplicate key for rows without a PinHunt ID using:

brand
+ series
+ pin name
+ character
+ release year

Normalise case, punctuation and whitespace before comparison.

Required validation

At minimum:

* Pin name must not be blank.
* PinHunt ID should match a format similar to PHUK-00000001.
* Year should be a reasonable four-digit number when present.
* Edition size should be numeric when present.
* Currency should use a normal code such as GBP, USD or EUR.
* URLs should be validated but should not block import if empty.
* Blank strings should be converted to null.
* Semicolon-separated characters and categories should be split and trimmed.
* Excel serial dates should be converted properly.
* Preserve Unicode characters and punctuation.

Rows with non-critical issues should still import with needs_review = true.

Rows with critical issues should be skipped and included in the error report.

Performance

Do not insert 13,000 records one at a time from the browser.

Use a server-side import process.

Recommended approach:

* Parse the Excel file server-side using the existing backend environment.
* Use the xlsx package or another suitable library.
* Validate and normalise all rows.
* Import in batches of approximately 250–1,000 records.
* Use Supabase upsert operations or a PostgreSQL function.
* Keep the UI responsive.
* Show processed row counts.

If the current Replit architecture supports background jobs, use one. Otherwise use a server-side endpoint that processes batches safely and reports progress.

Security

Only authenticated admins should be able to access the importer.

Do not expose the Supabase service role key to the browser.

Use server-side environment variables.

Add appropriate Row Level Security policies.

Normal app users must not be able to:

* Upload catalogue spreadsheets
* Bulk modify catalogue records
* Promote speculative records to verified without moderation
* Access raw import logs containing sensitive system details

* Refuse automatic deletion where imported records are already referenced by users, and instead mark them for admin review.
